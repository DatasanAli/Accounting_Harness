Bank statements

Fictional CSV · USD · January 2026

Import a fictional statement

Import records bank rows only. Your ledger and evidence stay unchanged. Matching and book adjustments will be separate actions.

The first successful import selects one bank account and permanently maps it to Cash 1000 in this workspace. Positive amounts increase bank cash; negative amounts decrease it.

CSV format and limits 
bank_account_id,transaction_id,booking_date,amount,currency,reference,description

Exact ordered headers; UTF-8; quoted commas and newlines supported. Use stable transaction IDs. Empty reference and description are allowed. Dates must fall inside the statement period in January 2026. Amounts use two decimal places, an optional minus, and no plus sign or zero movements.

Limits: 8,192 CSV bytes, 100 rows, 512 characters per cell, 80 per ID, 22 per amount; absolute cents at most 9,223,372,036,854,775,807. The entire JSON request must fit 16,384 bytes including escaping. An empty statement requires equal opening and closing balances.

Retry with the same metadata and original CSV bytes. Changed statement content, row order or file formatting under an existing statement ID conflicts. Unchanged transaction IDs may appear in overlapping statements.

Opening + movements must equal closing exactly. No journal will be posted.

The offline demo plays fixed fictional responses and makes no model calls. Select a provider on a receipt and explicitly run it to request a proposal.

For an installed local Ollama model, restart the server with:

python3 -m accounting_harness serve --enable-providers --ollama-model MODEL_NAME

For OpenAI, configure OPENAI_API_KEY in your local environment, then restart with --enable-providers. Keys stay out of this browser. API calls may be billable.

Live model accuracy, compatibility, latency, and billing remain unverified until the separate live evaluation. An available provider only means startup configuration allows requests.
