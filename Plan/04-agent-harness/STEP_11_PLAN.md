# Step 11: resumable fake-provider run loop

Goal: run the existing five typed tools under durable scope, checkpoints and budgets, survive interruption without duplicate draft revisions, and stop for human review. This implements the approved Step 11 brief only; no live provider, new accounting behavior or authentication.

## Design and recovery contract

`FakeProvider(outputs, timeouts={}, cost_units=1, latency_ms=1, prompt_version='script-v1')` snapshots a JSON script. Each output is one `{tool, arguments}` object or `{stop: concise_reason}`. Timeout counts by script index and integer simulated usage are trusted fixture configuration. Provider version is fixed `fake-v1`; fingerprint binds script, timeout schedule, prompt and usage. Scripts stay outside the run log; reopen must supply the same fingerprint. Invalid outputs are recorded as a reason code, not raw text or hidden reasoning. No sleeps, network or real billing.

`RunLimits(tool_calls, elapsed_ms, cost_units, retries)` uses nonnegative integers (positive elapsed_ms), with finite prototype ceilings. Cost is simulated integer units, never floating-point money. `SQLiteRunEngine(path, review_store)` owns a separate single-entity SQLite run file (application ID AHRN, schema v1). Bind exact ledger/registry paths, frozen ledger context, policy and tool schema digest; reject a mismatched scope. Preserve existing ledger/review/approval/source schemas. The caller restores all three databases together; independent restore/replacement of files is outside this prototype's recovery guarantee.

`start(run_id, task_id, provider, actor_id, limits)` atomically persists immutable config and initial checkpoint. Same run ID/config returns current state; changed config conflicts. Actor and entity come from trusted application configuration, never provider output. `advance(run_id, provider)` performs one provider preparation or tool execution; `run` advances until a stop. `resume` continues interrupted runnable work, or acknowledges an awaiting-review handoff as completed without more provider/tool calls. `cancel(run_id, actor_id, reason)` records cancellation and stops further calls. Terminal results are stable on retry. `get` and `trace` return immutable checkpoints; `configuration` returns canonical task/scope/provider/limit metadata without the raw script.

States: ready → pending_tool → executing_tool → ready/awaiting_review. Provider timeout can stay ready with a charged retry; transient storage lock failure returns pending_tool with a charged dispatch attempt. Any runnable state can become exhausted, failed or cancelled. Awaiting-review can become completed (handoff acknowledgement only) or cancelled. Provider stop/script end becomes completed if no draft was saved, otherwise awaiting_review. Completed/failed/exhausted/cancelled never restart; create a new explicit run for new work.

Provider attempts reserve deterministic cost/time and charge timeouts. Check real wall-clock elapsed time (including downtime) as well as cumulative simulated provider latency; use the greater, never decrease recorded elapsed time. Expiry, call and cost checks happen before new work. Tool dispatch attempts are durably reserved before execution and bounded to retries+1; a crash consumes its attempt. Retries cannot reset counters or extend budgets. Time is cooperative at local-call boundaries; this fake provider cannot block. A completed local call that crosses the deadline retains its result/draft reference and stops exhausted.

For each allowed call, persist a validated intent and count one tool call before invoking it. For `save_draft`, replace the provider's request key with a key derived from run ID, step and run-file scope, then persist it with the exact arguments. A second checkpoint reserves dispatch before the side effect. Hold a nonblocking OS advisory lock on a separate `.dispatch.lock` file across reservation commit and dispatch, and the SQLite write lock while executing. This supports the current macOS/Linux targets; a competing caller gets PersistenceBusy without consuming attempts. Process death releases the OS lock; the next caller may charge a recovery attempt if no receipt exists. Never delete the lock file during operation. Stale reservations cannot invoke tools. The existing review transaction commits the draft independently. If the process dies before the result checkpoint, lookup the exact durable review request and receipt on restart and record it without creating another revision or consuming a new budget unit. If no receipt exists, retry only within remaining time/attempts. Cancellation reconciles an already committed draft receipt but never executes a pending call. Lock failures and cancellation after a pending side effect preserve the intent and all evidence.

Checkpoints retain tool names/validated arguments needed for safe replay, concise reason codes, identities/digests and finding codes for results. Do not store raw provider outputs, entire evidence/tool responses or hidden reasoning. `request_review` pauses even when findings remain; all proposals still need a separate human action. No provider output can add tools, choose actor/storage/policy, or approve/post. Run-log writers are serialized for this local prototype; cancellation is observed between bounded local actions.
