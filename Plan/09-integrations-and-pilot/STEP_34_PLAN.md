# Step 34: synthetic release acceptance and deferred live gates

> **For agentic workers:** Use subagent-driven-development or executing-plans after verified Step 33.

**Goal:** Rehearse the complete supported fictional period through authenticated
workflows, produce traceable release evidence and leave the app ready for the
user's later LLM connection without claiming real-world pilot acceptance.

**Architecture:** One deterministic acceptance fixture drives delivered services;
one browser rehearsal proves the actual local workbench. Reuse existing scenarios,
reports and recovery checks. Add no unrelated accounting features or live transport.

**Tech stack:** Existing Python/SQLite tests, CLI and localhost UI.
**Spec:** [Phase 09](README.md), [overall request](../LOCALHOST_APP_PLAN.md).

## Global constraints and acceptance record

- The user deferred live APIs/providers/external accounts. No live evaluation,
  remote import/export or actual data permission may be marked successful here.
- Separate implemented/offline-verified, browser-demonstrated and deferred live
  gates. Name exact code commit, remote SHA and GitHub CI in release evidence.
- All fixtures are synthetic. Actual legal entity, reporting framework, fiscal
  calendar, jurisdiction, capitalization/recognition/correction policies, approved
  operators and retention expectations remain an explicit real-data pilot gate.
- No model or preparer approval/posting, no unauthorized entity read/write and no
  unbalanced/unsupported entry may succeed. Stop and fix any load-bearing failure
  before claiming the offline objective complete.

## Rehearsal scope

Start from a fresh authenticated synthetic workspace with preparer and reviewer.
Register the Step20d operational variant's ordinary evidence (its insurance purchase
is explicitly Jan1, while the original fixture remains untouched) and prepare/post through supported
application workflows; do not seed authoritative journals or managed effects by
SQL. Reproduce T01–T09 plus the supported 100.00 insurance allocation and 200.00
advance earning, keeping the separate accrual/bank-fee examples outside those
reference totals. Expected ordinary adjusted statements: revenue 2,700.00,
expenses 1,600.00, income 1,100.00, assets 11,500.00, liabilities 600.00 and equity
10,900.00; Cash 9,400.00. Preserve all subsidiary control reconciliations.

Produce captured statements and cash flow, JSON/CSV-manifest export/readback,
then explicit close/lock with post-close trial balance 11,500.00 per side and
capital 10,900.00. Historical pre-close reports remain exact after closing;
forbidden backdated posts fail. Link the published independent reference fixture.

Use separate smaller scenarios for bank import/match/fee/timing/reconciliation,
unbilled expense/revenue accruals, projects/time/model cost, budgets/flexible
variances/contribution/KPIs, offline integration import/export and recovery. Assert
each published reference result without contaminating the accounting-month totals.
Management assumptions never create actual journals. Include a zero-difference
bank exception and a lost simulated export response to demonstrate honest failure
states rather than a happy-path-only acceptance.

Run the operational agent contract corpus through offline/mock transports and
show a pending draft with zero posting effects, then separately authenticate the
reviewer to post. Demonstrate missing/hostile/conflicting evidence handoff, stale
approval rejection, denied preparer/agent/cross-entity actions, revocation, restart
and recovery with no duplicate effects. Live model quality remains unmeasured.

The setup runbook must give exact commands to provision local users, start the UI,
select/configure Ollama or frontier API without exposing credentials to the
browser, run offline demonstrations and back up/restore. Configuration alone is
not a verified connection. Explain the supported synthetic USD/January boundary,
unsupported corrections/settlements and actual-pilot decisions plainly.
